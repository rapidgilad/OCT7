# Plan: finish v0.1, the first playable skirmish (phases 6–8)

## Context
The goal of v0.1 was already approved: a **1v1 skirmish vs AI with all 3 factions and rough low-poly graphics (not boxes)**. You launch the game, pick your faction, the enemy faction and difficulty, then play a full match until victory or defeat by VP tickets or HQ destruction. The direction was "game first, balance later".

**Done and pushed** on `claude/coh-rts-game-design-06vm8t` (phases 1–5):
- The deterministic sim: data, maps, cover, vision, combat, suppression, retreat and reinforce, territory, tickets and victory, production, construction, sandbags.
- SkirmishAi with Easy, Normal and Hard.
- Full-match MatchRunner and 92 tests.

**Written but not yet compiled or committed** (phases 6–7, still on disk after the worker restart):
- Visuals: `Visual/MeshKit.cs` and `Visual/ModelFactory.cs` (procedural soldiers, vehicles, structures and props).
- Views: `SquadView`, `StructureView`, `ViewRegistry`, `MapView`, `SectorView`, `GroundOverlays` (fog and territory).
- Effects: `Vfx/VfxManager.cs`.
- Input: `Input/PlayerController.cs`.
- UI: `UiTheme`, `Hud` (top bar, command card, production queue), `Minimap`, `OverlayLayer`, `Menus` (EndScreen, PauseMenu), `MainMenu`.
- Launch flow: `LaunchOptions` (new `--quick`, `--difficulty`, `--map`, `--full-match` and `--fog`, plus `SkipMenu` and `ApplyTo()`) and `MatchSettings` (`LaunchHandled`, `Launch`).
- Sim: a new `SurrenderCommand` with a test.

**What remains:** the match host that wires all of this together, the scenes, compiling, verification through screenshots, then docs, CI and the push.

## Step 1: Match host and scenes
- **New file `game/scripts/Match/MatchController.cs`** (`partial class : Node3D`). These are the members the other scripts already reference:
  - `Sim`, `LocalPlayerId` (0), `Paused`, `Hud`, `Views`, `CameraRig`, `Player`.
  - `Enqueue(Command)` is ignored in demo mode or after the match ends. `TogglePause()`. `Surrender()` enqueues `SurrenderCommand` and unpauses.
- **`_Ready`:**
  - Consume the launch options:
    - If `MatchSettings.LaunchHandled` is false (the scene was run directly), parse and apply the options.
    - Take `MatchSettings.Launch` and then null it, so "Play again" or a return to the menu won't repeat a screenshot or fast-forward.
  - Load and validate the data with `GodotDataSource.Load()` and `GameDataValidator.Validate`.
  - Create the match with `MatchSetup.CreateSkirmish(data, PlayerFaction, EnemyFaction, Seed, MapId)`.
  - Create the AIs with `SkirmishAi.Create(sim, 1, Difficulty)`. Player 0 also gets an AI in demo and smoke-test runs.
  - Smoke test: loop `SimLoop.Step` (`sim/AI/AiControllers.cs`).
    - With `--full-match`, stop at `IsOver`.
    - Print the ticks, winner and state hash.
    - Exit 1 if the data is invalid, or if `--full-match` was given and no side won.
  - Fast-forward N ticks, or until the end with `--full-match`. Then call `InputSetup.EnsureActions()` and build the world.
- **Build the world.** Reuse the pieces that already exist:
  - Scene: `SceneSetup` environment and sun; `MapView.Build`; `SectorView.Build`.
  - Overlays: `GroundOverlays`, with fog off when everything is revealed.
  - Views and effects: `ViewRegistry`, then `VfxManager.Initialize`. Both get `LocalPlayerId` and `RevealAll`, which is demo without `--fog`.
  - Camera: `RtsCamera` starts at your HQ, facing the map center (for HQ (60,60) on the 300 m map, that is yaw 225°). It also handles `--overview` and `--focus-army`.
  - Input: `PlayerController.Initialize`.
  - UI: a `CanvasLayer` holding, in order, OverlayLayer, Hud (+ `Hud.Minimap.Initialize(this, mapView.GroundTexture)`), PauseMenu and EndScreen.
  - Tools: `ScreenshotTool`; `--select-all`.
- **`_Process`:**
  - Run a fixed 10 Hz step with an accumulator capped at 0.25 s, skipped while paused or after the match is over.
  - After each step, send `Sim.Events` to `Views.OnEvent`, `Vfx.OnEvent` and `Hud.OnEvent`, and count the end-screen stats.
  - Then call `Views.Sync(...)`, `SectorView.UpdateVisual()` and `GroundOverlays.UpdateOverlays(sim)`.
  - When the match ends, show the EndScreen once.
    - The reason comes from the loser's `PlayerState`: tickets exhausted, HQ destroyed, or surrender.
    - Stats: match time, squads fielded / lost / destroyed, and sectors held.
- **Small edits to existing files:**
  - `ViewRegistry.Sync` takes `IReadOnlyCollection<int>`, which matches `PlayerController.SelectedSquads`.
  - `RtsCamera.FocusOn(Vector3)`, which the minimap uses.
  - Move the nested `CorpseAnimator` out of `SquadView.cs` into its own file, `Views/CorpseAnimator.cs`, so the file name matches the class name (golden rule 6).
  - Add a `--menu` launch flag, so the menu can be screenshotted.
- **Scenes:**
  - Create `game/scenes/menu.tscn` (Control + `UI/MainMenu.cs`) and `game/scenes/match.tscn` (Node3D + `Match/MatchController.cs`).
  - Set `project.godot` `run/main_scene` to `res://scenes/menu.tscn`.
  - Delete the old `Main.cs`, `scenes/main.tscn`, `Input/SelectionController.cs` and `UI/DebugHud.cs`, along with their `.uid` files.

## Step 2: Compile and check
1. Run `dotnet build OCT7.sln` and fix the compile errors. Known suspect: the type of `ProgressBar.FillMode` in `Hud.cs`.
2. Run `godot --headless --path game --import` to generate the `.uid` files for the new scripts; they get committed.
3. Run `dotnet test tests/OCT7.Sim.Tests` (93 tests) and `dotnet format whitespace OCT7.sln --verify-no-changes`.
4. Run the headless smoke tests:
   - `--smoke-test 600` should give the same hash as MatchRunner for the same seed and factions.
   - `--smoke-test 30000 --full-match` should exit 0 with a winner.
5. **Commit and push**, "v0.1 phases 6-7: procedural visuals, HUD, menus, match host". This secures the work in the ephemeral container.
